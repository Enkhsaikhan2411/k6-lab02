# Лаб 2: k6 Performance Testing

F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест (2026)

## Юу хийсэн бэ

- Grafana k6 суулгаж, performance testing хийх орчноо бэлдсэн.
- `https://test.k6.io` сайт дээр ачааллын тест хийсэн.
- 5, 30, 100 хэрэглэгч зэрэг хандах үед ямар үр дүн гарахыг тус тусад нь шалгасан.
- Stages test ашиглан хэрэглэгчийн тоог 5-аас 30, дараа нь 100 болгож нэмээд эцэст нь 0 болгож бууруулсан.
- Baseline тестийн үр дүнд үндэслэн threshold тохируулсан:
  - Response time: p(95) < 800 ms
  - HTTP error rate: < 1%
- Threshold-ээ шалгахын тулд нэг PASS, нэг FAIL тест ажиллуулсан.
- Бүх тестийн үр дүнг `results/` хавтсанд `.txt` файлаар хадгалсан.

## Тест ажиллуулах

```bash
k6 run script.js
k6 run stages.js
k6 run threshold-pass.js
k6 run threshold-fail.js
```

Үр дүнг файлд хадгалахдаа:

```bash
k6 run script.js > results/run-05vu.txt 2>&1
```

## Файлын бүтэц

- `script.js` — 5 хэрэглэгчтэй baseline тест
- `stages.js` — хэрэглэгчийн тоог үе шаттай өөрчлөх тест
- `threshold-pass.js` — threshold шаардлагыг хангасан тест
- `threshold-fail.js` — response time-ийн шаардлагыг хангаагүй тест
- `results/run-05vu.txt` — 5 хэрэглэгчийн тестийн үр дүн
- `results/run-30vu.txt` — 30 хэрэглэгчийн тестийн үр дүн
- `results/run-100vu.txt` — 100 хэрэглэгчийн тестийн үр дүн
- `results/run-stages.txt` — stages тестийн үр дүн
- `results/threshold-pass.txt` — PASS тестийн үр дүн
- `results/threshold-fail.txt` — FAIL тестийн үр дүн

## k6 ашигласан миний ажиглалт

Энэ лабораторийн ажлаар k6 ашиглан веб сайт дээр ачааллын тест хэрхэн хийхийг туршиж үзсэн. Эхлээд 5 хэрэглэгчтэй baseline тест ажиллуулаад, дараа нь 30 болон 100 хэрэглэгчтэй үед үр дүн нь хэрхэн өөрчлөгдөхийг харьцуулсан. Хэрэглэгчийн тоо нэмэгдэх тусам нэг секундэд боловсруулсан хүсэлтийн тоо нэмэгдэж байсан ч 100 хэрэглэгчтэй тестийн p95 response time 844.8 ms болсон. Миний хийсэн тестүүдэд HTTP error rate 0% гарсан нь сонирхолтой байлаа. Мөн stages ашиглан хэрэглэгчийн тоог аажмаар нэмэгдүүлж, бууруулж үзсэн. Threshold тохируулахдаа baseline-ийн p95 утгыг ашиглаж 800 ms гэсэн босго сонгосон. PASS тестэд энэ шаардлага биелсэн бол FAIL тестэд 50 ms гэсэн хэт бага босго тавьсан учраас тест амжилтгүй болсон. Ингэснээр серверийн хүсэлт амжилттай хариулах болон гүйцэтгэлийн шаардлага хангах хоёр өөр зүйл гэдгийг ойлгосон.
